## Goal

Understand what Interfaces are, why they are important, how they enforce contracts in applications, and how Angular heavily relies on interfaces for models, APIs, services, and enterprise application development.

---

# What

An Interface is a blueprint or contract that defines what properties and methods an object must have.

In simple words:

```text
Interface tells us what an object should look like.
```

---

## Real-Life Example

Imagine a job application form.

Every applicant must provide:

```text
Name
Email
Phone Number
```

The form defines the structure.

Similarly:

```text
Interface defines structure.

Objects follow structure.
```

---

## Example

### Without Interface

```typescript
let trainer = {

    name: "Deepak",

    technology: "Angular"

};
```

No standard contract.

---

### With Interface

```typescript
interface Trainer {

    name: string;

    technology: string;

}

let trainer: Trainer = {

    name: "Deepak",

    technology: "Angular"

};
```

Now structure is enforced.

---

# Why

Without Interfaces:

```text
Different developers create
different object structures.

Confusion occurs.
```

Example:

Developer 1:

```typescript
{
    name: "Deepak"
}
```

Developer 2:

```typescript
{
    trainerName: "Deepak"
}
```

Developer 3:

```typescript
{
    employeeName: "Deepak"
}
```

---

With Interface:

```typescript
interface Trainer {

    name: string;

}
```

Everyone follows same contract.

Benefits:

```text
Consistency
Maintainability
Readability
Scalability
```

---

# How It Works

## Interface Flow

```text
Interface
      ↓
Defines Contract
      ↓
Object Follows Contract
      ↓
Compiler Validates
```

---

## Example

```typescript
interface Employee {

    id: number;

    name: string;

}
```

Object:

```typescript
let emp: Employee = {

    id: 101,

    name: "Deepak"

};
```

Compiler verifies structure.

Not mandatory.

```typescript
    name: string;

    email?: string;

}
```

Usage:

```typescript

    id: 1,

    name: "Amit"

};
```

Valid.

---

## Lab 5: Readonly Property

### What

Cannot be modified.

```typescript
interface Employee {

    readonly id: number;

    name: string;

}
```

Usage:

```typescript
let emp: Employee = {

    id: 101,

    name: "Deepak"

};
```

Invalid:

```typescript
emp.id = 200;
```

Compiler Error.

## Lab 7: Class Implementing Interface

### Interface

```typescript
interface Employee {

    id: number;

    name: string;

}
```

### Class

```typescript
class Trainer
implements Employee {

    id: number;

    name: string;

    constructor(
        id: number,
        name: string
    ) {

        this.id = id;

        this.name = name;

    }

}
```

Usage:

```typescript
let trainer1 =
    new Trainer(
        101,
        "Deepak"
    );

console.log(trainer1);
```
