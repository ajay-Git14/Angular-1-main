## Goal

Understand why decorators exist, how they work and how Angular uses `@Component`, `@Injectable`, `@Input`, `@Output`, `@HostListener`, `@Directive`, `@Pipe`, and `@NgModule`. By the end you should be able to **compile, run and troubleshoot** each example.

## What — and why the earlier examples failed

A decorator is a function invoked when a decorated class or class element is **defined**. It can observe or modify a definition, or associate information with it. Angular decorators describe framework-managed classes and members; importing `@Component` by itself is **not** sufficient to run Angular code in plain Node.js.

**Real-life analogy:** A trainer is a normal person; a *Senior Trainer* role communicates additional responsibility and configuration. A decorator similarly labels/configures a program element, but is a real function rather than only a comment.

**Memory hook:** `Decorator = definition-time function + framework/behavioral configuration`.

### Critical distinction: two incompatible decorator systems

| | Legacy TypeScript / Angular-style decorators | Standard TypeScript 5+ decorators |
|---|---|---|
| TypeScript config | `experimentalDecorators: true` | `experimentalDecorators: false` or absent |
| Method decorator signature | `(target, propertyKey, descriptor)` | `(value, context)` |
| Property decorator | `(target, propertyKey)` | Field decorator `(initialValue, context)` |
| Parameter decorator | Supported | **Not supported** |
| Best use here | Labs 1–5, Angular teaching | Bonus modern TS example |

Choose **one** decorator model per compiled file/project. Decorators do **not** run at each object construction by default, and a property decorator alone does **not** intercept instance property assignments.

## Lab 1: First Decorator — class logger

**File:** `src/legacy/01-logger.ts`. Compile using `npm run build:legacy` then execute `node dist/legacy/01-logger.js`.

```typescript
export {}; // Give each lab its own module scope.
// Lab 1. Legacy class decorator: executed when the class is defined.
function Logger(_constructor: Function): void {
  console.log('Class decorator executed');
}

@Logger
class Trainer {
  teach(): string {
    return 'Teaching TypeScript';
  }
}

const trainer = new Trainer();
console.log(trainer.teach());
```

**Verified output**

```text
Class decorator executed
Teaching TypeScript
```

## Lab 3: Method Decorator — wrap method behavior

**File:** `src/legacy/03-method.ts`. Compile using `npm run build:legacy` then execute `node dist/legacy/03-method.js`.

```typescript
export {}; // Give each lab its own module scope.
// Lab 3. A method decorator wraps the original implementation.
function LogMethod(
  _target: object,
  propertyKey: string | symbol,
  descriptor: PropertyDescriptor
): void {
  const original = descriptor.value as (topic: string) => string;
  descriptor.value = function (this: Trainer, topic: string): string {
    console.log(`Calling ${String(propertyKey)} with ${topic}`);
    return original.call(this, topic);
  };
}

class Trainer {
  @LogMethod
  teach(topic: string): string {
    return `Teaching ${topic}`;
  }
}

console.log(new Trainer().teach('Decorators'));
```

**Verified output**

```text
Calling teach with Decorators
Teaching Decorators
```

## Challenge lab: Angular Metadata Simulator (no Angular needed)

Simulate class registration with a `Map`, preserving the assignment from the original document. This is **not** Angular's runtime/metadata system.

```typescript
export {}; // Give each lab its own module scope.
// Challenge assignment: simulate decorator-based registration.
// This is NOT the Angular runtime; it uses our own Map as registry.
interface Metadata {
  kind: 'component' | 'service';
  selector?: string;
}

const registry = new Map<Function, Metadata>();

function ComponentLike(selector: string): ClassDecorator {
  return (target: Function): void => {
    registry.set(target, { kind: 'component', selector });
  };
}

function InjectableLike(): ClassDecorator {
  return (target: Function): void => {
    registry.set(target, { kind: 'service' });
  };
}

@ComponentLike('app-home')
class HomeComponent {}

@InjectableLike()
class UserService {}

console.log(JSON.stringify(registry.get(HomeComponent)));
console.log(JSON.stringify(registry.get(UserService)));

if (registry.size !== 2) {
  throw new Error('Expected two registered classes');
}
```

**Verified output**

```text
{"kind":"component","selector":"app-home"}
{"kind":"service"}
```

## Bonus: TypeScript 5+ standard decorator example

Use the separate **standard** configuration; do **not** turn on `experimentalDecorators` for this file.

```typescript
export {}; // Give each lab its own module scope.
// TypeScript 5+ standard decorators: NO experimentalDecorators flag.
function Registered(_value: Function, context: ClassDecoratorContext): void {
  console.log(`Registered class: ${String(context.name)}`);
}

function Trace<This, Args extends unknown[], Return>(
  original: (this: This, ...args: Args) => Return,
  context: ClassMethodDecoratorContext<This, (this: This, ...args: Args) => Return>
): (this: This, ...args: Args) => Return {
  return function (this: This, ...args: Args): Return {
    console.log(`Calling ${String(context.name)}`);
    return original.apply(this, args);
  };
}

@Registered
class Trainer {
  @Trace
  teach(topic: string): string {
    return `Teaching ${topic}`;
  }
}

console.log(new Trainer().teach('Modern Decorators'));
```

**Verified output**

```text
Registered class: Trainer
Calling teach
Teaching Modern Decorators
```

### Complete `src/app/app.ts` for Labs 6–13

```typescript
// Lab 6-13. Copy into src/app/app.ts of a NEW standalone Angular CLI app.
import {
  Component,
  Directive,
  EventEmitter,
  HostBinding,
  HostListener,
  Injectable,
  Input,
  NgModule,
  Output,
  Pipe,
  PipeTransform,
  inject
} from '@angular/core';
import { CommonModule } from '@angular/common';

// Lab 7: injectable service.
@Injectable({ providedIn: 'root' })
export class UserService {
  welcome(): string {
    return 'Welcome from UserService';
  }
}

// Labs 8 and 9: decorated input and output must be inside a class.
@Component({
  selector: 'app-child',
  standalone: true,
  template: `
    <p>Child title: {{ title }}</p>
    <button type="button" (click)="save.emit()">Save</button>
  `
})
export class ChildComponent {
  @Input() title: string = '';
  @Output() save = new EventEmitter<void>();
}

// Labs 10 and 11: a directive can react to host events.
@Directive({ selector: '[appHighlight]', standalone: true })
export class HighlightDirective {
  @HostBinding('style.backgroundColor') backgroundColor = 'transparent';

  @HostListener('mouseenter') onEnter(): void {
    this.backgroundColor = 'lightyellow';
  }

  @HostListener('mouseleave') onLeave(): void {
    this.backgroundColor = 'transparent';
  }

  @HostListener('click') onClick(): void {
    console.log('Highlighted element clicked');
  }
}

// Lab 12: a pipe must provide transform().
@Pipe({ name: 'currencyFormat', standalone: true })
export class CurrencyFormatPipe implements PipeTransform {
  transform(value: number): string {
    return new Intl.NumberFormat('en-IN', {
      style: 'currency',
      currency: 'INR'
    }).format(value);
  }
}

// Lab 13: a classic NgModule example. Declared components must be
// standalone: false; the module can be imported into a standalone app.
@Component({
  selector: 'app-legacy-greeting',
  standalone: false,
  template: '<p>Hello from NgModule component</p>'
})
export class LegacyGreetingComponent {}

@NgModule({
  declarations: [LegacyGreetingComponent],
  imports: [CommonModule],
  exports: [LegacyGreetingComponent]
})
export class LegacyExampleModule {}

// Lab 6: complete root component that exercises every Angular lab.
@Component({
  selector: 'app-root',
  standalone: true,
  imports: [ChildComponent, HighlightDirective, CurrencyFormatPipe, LegacyExampleModule],
  template: `
    <h1>Angular Decorators Lab</h1>
    <p>{{ welcomeMessage }}</p>
    <app-child [title]="'TypeScript Decorators'" (save)="onSave()" />
    <p>{{ status }}</p>
    <p appHighlight>Hover over or click this highlighted paragraph.</p>
    <p>Formatted price: {{ 1250 | currencyFormat }}</p>
    <app-legacy-greeting />
  `
})
export class App {
  welcomeMessage = inject(UserService).welcome();
  status = 'No save event yet';

  onSave(): void {
    this.status = 'Save event received from child';
  }
}
```

## Troubleshooting

| Error / symptom | Likely cause | Fix |
|---|---|---|
| `TS1241` / decorator signature mismatch | Legacy decorator signature compiled as modern decorator | Use `tsconfig.legacy.json` with `experimentalDecorators: true` |
| `TS1206: Decorators are not valid here` | Parameter decorator under standard syntax / misplaced decorator | Compile legacy parameter example with the legacy config; put decorators on valid class elements |
| `Cannot find name 'Component'` | Missing Angular import/package or Angular snippet pasted into plain TS | Run inside Angular CLI project with `import { Component } from '@angular/core'` |
| `@Pipe` class type error | Missing `transform` method | Implement `PipeTransform.transform` as in Lab 12 |
| Component listed in `NgModule` declarations is standalone | A standalone component cannot be declared in `declarations` | Set `standalone: false` for declared components, or import standalone ones instead |
| `Can't bind to 'title'` | Child is not imported or input is not declared | Add child to parent `imports` and `@Input() title` |
| Decorator logs earlier than method call | Class decorators run at class definition | This is expected; distinguish definition-time execution from invocation |
| Duplicate identifier `Trainer` | Multiple labs pasted into one global script | Run separate files with `export {}` module scope |

## Production and interview notes

- Decorators help keep framework configuration close to the class/member; they are not a replacement for understanding dependency injection, type checking, or runtime behavior.
- Legacy property/parameter decorators can observe definitions, but do not automatically validate or inject values.
- Angular also supports newer signal-based `input()` and `output()` APIs. This lesson intentionally uses traditional decorator-based APIs to teach decorators.
- Explain **legacy vs standard** decorators before showing a TypeScript 5+ interview implementation.
