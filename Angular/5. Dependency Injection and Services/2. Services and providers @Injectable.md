## Goal

Understand Angular Services, learn how business logic is separated from Components, and understand how Providers and the @Injectable decorator work in enterprise Angular applications.

---

# What

A Service is a TypeScript class that contains reusable business logic.

Without Services:

```text
Component

UI Logic
Business Logic
API Logic
Validation Logic

Everything Mixed Together
```

---

With Services:

```text
Component
      ↓
UI Logic

Service
      ↓
Business Logic

API Logic

Data Processing
```

Angular applications become cleaner and easier to maintain.

---

# Real-Life Analogy

Imagine a hospital.

Doctor:

```text
Examines Patient
```

Laboratory:

```text
Processes Reports
```

Pharmacy:

```text
Provides Medicines
```

Everyone has a dedicated responsibility.

Similarly:

```text
Component
      ↓
UI

Service
      ↓
Business Logic
```

# Providers

## What?

Providers tell Angular how to create dependencies.

---

## Lab 8

```typescript
@Component({

providers:[

ComplaintService

]

})
```

---

Result:

```text
Component Specific Instance
```

---

# Root Provider vs Component Provider

| Root Provider     | Component Provider |
| ----------------- | ------------------ |
| One Instance      | Multiple Instances |
| Shared Everywhere | Local To Component |
| Singleton         | Non-Singleton      |
| Common Usage      | Special Cases      |
