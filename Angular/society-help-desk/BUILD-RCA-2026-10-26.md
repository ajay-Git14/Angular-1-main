# Angular Build Failure — RCA and Fix (26 October 2026)

## Evidence supplied by the learner

\`npm run build\` produced two independent classes of errors:

1. **TS2741** in \`src/lab/course-catalog.ts\`: 26 Chapter 03 live subtopics had \`id\`, \`kind\`, \`category\` but omitted required \`CourseSubtopic.name\`. The literal course data was validated as \`readonly CourseChapter[]\` before the \`COURSE_CHAPTERS\` mapper added its display name, so the TypeScript compiler correctly rejected it.
2. **NG5002, TS2339 and TS2345** in \`src/lab/lab-demo.html\`: eight \`(click)\` expressions contained lambdas like \`visible.update(v => !v)\`. Angular templates do not accept arrow-function definitions in binding expressions. The follow-up \`v\` and undefined callback errors were cascading consequences of the same invalid template syntax.

## Code correction

**Catalog:** Each of the 26 live subtopic seed objects now has a nonempty \`name\` aligned with the existing executable \`LAB_TOPICS\` title. The original mapping still resolves the canonical name from the demo catalogue. All 11 chapters, 59 topics, 857 subtopics, and 26 live examples are preserved.

**Angular template:** Replace lambda declarations with supported signal expressions that evaluate the current signal and call its setter.

Incorrect:

~~~html
<button (click)="visible.update(v => !v)">Toggle</button>
~~~

Correct:

~~~html
<button (click)="visible.set(!visible())">Toggle</button>
~~~

The correction applies to \`highPriority\`, \`showAlert\`, \`visible\`, and \`active\` across eight \`(click)\` event bindings. No state variables or demo screens were removed.

## Prevention

Two additional dependency-free Node regression tests were added to \`scripts/lab-acceptance.test.mjs\`:

- Every live curriculum subtopic must have a nonblank \`name\`.
- No Angular HTML event-binding attribute may contain an inline arrow function.

These are **static checks, not Angular compilation**. The Angular production build remains the definitive compile check.
