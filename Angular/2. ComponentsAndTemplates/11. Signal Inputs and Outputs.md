# Topic 11 — Modern Signal Inputs and Outputs

## Goal
Understand parent-to-child data and child-to-parent events using Angular's modern APIs.

**Project exercise:** Continue the [Society Help Desk Module 02 project](./PROJECT-LAB-M02-SOCIETY-HELP-DESK.md). Follow its **Step 03 — Reusable complaint card** and **Step 04 — Dashboard**. The code introduces `complaint = input.required<Complaint>()` (the child reads it as `complaint()`), plus `resolved = output<number>()` (the child calls `resolved.emit(id)`). The parent passes `[complaint]="item"` and receives `(resolved)="resolveComplaint($event)"`.

### Verify
1. Start `ng serve --open` in your Society Help Desk workspace.
2. Confirm three complaint cards are visible.
3. Click **Mark resolved** on the water issue.
4. Confirm open count drops from 2 to 1 and its button is disabled.
5. Temporarily omit `[complaint]` from one card use and observe the required-input compiler error; restore it.

**Memory hook:** *Input receives; output announces.* Signal inputs are read using parentheses, unlike classic `@Input` properties. `output()` is an event emitter, not a signal.

**Practice:** Show a second complaint card and explain why each card can receive a different object even though both reuse the same component.

**Evidence:** Screenshot of the resolved state and one-minute explanation of data/event direction.

**Reference:** https://angular.dev/guide/components/inputs · https://angular.dev/guide/components/outputs
