# Topic 3: Displaying Data using @for, @if, @switch
## Goal

Understand Angular's modern Control Flow syntax using `@if`, `@for`, and `@switch`, and learn how to display dynamic data efficiently in Angular applications.

---

# What

Angular provides modern control flow statements to dynamically display content.

These are:

```text
@if

@for

@switch
```

They replace older syntax:

```text
*ngIf

*ngFor

ngSwitch
```

with a cleaner and more readable approach.

---

# Why

Modern Angular applications display:

* User Lists
* Product Lists
* Employee Records
* Dashboard Statistics
* Conditional Messages
* User Roles
* Dynamic Menus

Without control flow:

```text
Static UI

No Dynamic Content

Poor User Experience
```

With control flow:

```text
Dynamic UI

Conditional Rendering

Loop Rendering

Role-Based Screens
```

---

# Real-Life Analogy

Imagine a restaurant.

### @if

```text
If Customer Is VIP

Show VIP Lounge
```

---

### @for

```text
For Every Customer

Generate Bill
```

---

### @switch

```text
If Customer Type

VIP → Lounge

Regular → Main Hall

Guest → Waiting Area
```

## Key Takeaways

```text
@if displays conditional content.

@for displays collections.

track improves performance.

@empty handles empty collections.

@switch handles multiple conditions.

Modern Angular prefers @if, @for and @switch.
```

## Beginner hands-on lab — Control flow

**Outcome:** Create a visible result in the browser and explain the smallest working pieces. Allow 20–35 minutes after reading the lesson.

**Before you start:** Complete [Module 01 setup](../1.%20Fundamentals/00.%20START%20HERE%20-%20Hands-on%20Beginner%20Lab.md); open your Angular workspace in VS Code. Use `ng version` to confirm the CLI. Your application should be a modern **standalone-component** project. The CLI may generate `<name>.ts` or `<name>.component.ts`; inspect the actual files and exported class/selector.

### Follow along

1. Open **Terminal → New Terminal** in VS Code. Ensure you are in the directory containing `angular.json`.
2. Generate the example component:

```bash
ng generate component order-status
```

3. In `src/app/order-status/`, find the generated component HTML file. Replace its **template only** with:

```html
@if (orders.length > 0) {
  @for (order of orders; track order.id) {
    @switch (order.status) {
      @case ('delivered') { <p>{{ order.id }}: Delivered</p> }
      @case ('pending') { <p>{{ order.id }}: Pending</p> }
      @default { <p>{{ order.id }}: Unknown</p> }
    }
  }
} @else { <p>No orders yet</p> }
```

4. Open the component's matching TypeScript file, **keep** its `@Component` decorator, existing imports and exported class, and apply the following instructions:

Add `orders = [{id: 1, status: 'delivered'}, {id: 2, status: 'pending'}];` to the component class. Import and display the component in root.

5. Save changes (**Ctrl+S**). If the development server is not running, execute `ng serve --open`, then inspect **http://localhost:4200/** (or the port printed in the terminal).
6. Exercise the displayed control or read the output, as appropriate. Use **F12 → Console** if a lifecycle log or exception needs inspection.

### Verify your result

- [ ] Angular compiles without template or TypeScript errors.
- [ ] The generated component appears in the root page (not only as files on disk).
- [ ] The display or user interaction behaves as described above.
- [ ] You can point to the relevant class member and its template expression.

### Common problems and fixes

| Symptom | First check |
|---|---|
| `ng` not recognized | Node.js/CLI installation and terminal PATH; run `ng version` |
| Not inside an Angular workspace | Open the folder containing `angular.json` |
| Unknown custom element | Import the child class in the root standalone component's `imports`; match its selector |
| Property or method missing | Match class member names and template spelling exactly |
| Nothing changes on screen | Ensure the edited HTML is the file referenced by the child's `templateUrl`; save changes |

## Beginner practical — Control flow

**Goal:** Follow a complete small exercise, see the result, and explain it. First complete the setup in [Module 01 workbook](../1.%20Fundamentals/00.%20START%20HERE%20-%20Hands-on%20Beginner%20Lab.md).

1. Open VS Code in the Angular project folder (the folder containing `angular.json`). Run `ng version` to verify installation.
2. In VS Code Terminal run `ng generate component status-board`.
3. Open the new component HTML file in `src/app/status-board/` (find its actual `templateUrl`) and replace its markup:

```html
@if (items.length) { @for (item of items; track item) { @switch (item) { @case ('Open') { <p>Open</p> } @default { <p>{{ item }}</p> } } } } @else { <p>Empty</p> }
```

4. **Update TypeScript:** Add items = ['Open', 'Closed'] inside class; import component into root and render its selector. Keep existing imports, decorator and exported class. Newer and older CLI projects generate different class/file names; copy the names from your own files.
5. Run `ng serve --open`; inspect the page at the localhost address shown. Save files with Ctrl+S.

**Expected result:** The status-board component appears in the browser and its content or click interaction behaves according to the markup.

**If it fails:** 'Unknown element' means add the child to the root standalone component's `imports`; missing property means match the TypeScript field name; nothing appears means check the root template and component selector.

**Practice:** Change the displayed text or one data value; predict the result first, then confirm it. Capture a screenshot and explain where the value comes from.

**Memory hook:** Component class = logic; template = screen; bindings = connection.
