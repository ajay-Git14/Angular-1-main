## Goal

Build a schema-driven Society Help Desk complaint form using Angular 20-compatible reactive forms, `FormRecord`, `FormArray`, `FormControl`, validation metadata and `@for`/`@switch` template control flow. Connect each lab to the Chapter → Topic → Subtopic → Execution application.

## What and Why

Ordinary reactive forms list every field in source code. Dynamic forms use a *field definition* (name, input type, required flag and dropdown options) to construct an interactive form. A housing society may need different questions for Water, Lift, Parking and Security complaints.

A metadata-driven form is useful when fields change by business rule or configuration. It still requires explicit validators, accessible field labels, safe types, and server-side validation in a real production application.

## Real-life analogy and memory hook

**Analogy:** A receptionist selects a questionnaire template for a complaint category; the printed form changes without rebuilding the reception desk.

**Memory hook:** **Blueprint (schema) → Controls (FormRecord) → View (@for) → Validation → Submission.**

## Angular architecture map

~~~text
FieldMetadata[]
     ↓ map field.key → control + validators
FormRecord<FormControl<string>>
     ↓ [formGroup] and [formControlName]
@for / @switch responsive form renderer
     ↓ Angular state / errors / dirty / touched
Local preview (no backend / no passwords)
~~~

## Prerequisites

Angular 20.3 Society Help Desk from this repository, Forms/ReactiveFormsModule knowledge, TypeScript interfaces, and Chapter 04 Topics 1–5.

## Suggested approach

Use a FormRecord for an open-ended collection of same-type controls. When you need repeated groups, use a FormArray. For a stable, known schema, a regular typed FormGroup may be simpler and safer. Updating metadata alone is insufficient: also add/remove the corresponding Angular form controls.

## Known pitfalls / Troubleshooting

- **Cannot find control with name:** metadata and FormRecord keys differ. Create/add the control before rendering it.
- **Form is invalid despite fields being filled:** inspect `errors` and call `updateValueAndValidity` when validators change.
- **Duplicate keys in @for:** choose a unique metadata `key` and `track field.key`.
- **Mixing ngModel and formControlName:** avoid using both on the same input.
- **Accidental upload:** This training application shows the selected filename only; no file is transmitted.
