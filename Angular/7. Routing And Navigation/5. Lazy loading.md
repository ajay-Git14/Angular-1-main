# Topic 5: Lazy Loading

## Goal

Understand Lazy Loading in Angular, learn how Angular loads modules only when needed, and build high-performance enterprise applications with optimized startup time and reduced bundle size.

---

# What

Lazy Loading is a technique where Angular loads modules only when the user visits them.

Without Lazy Loading:

```text
Application Starts
        ↓
Load All Modules
        ↓
Large Bundle
        ↓
Slow Startup
```

---

With Lazy Loading:

```text
Application Starts
        ↓
Load Only Required Module
        ↓
User Opens Feature
        ↓
Load Feature Module
```

---

# Real-Life Analogy

Imagine a hotel.

Without Lazy Loading:

```text
All Rooms

All Lights

All AC Units

Turned On
```

Wasteful.

---

With Lazy Loading:

```text
Guest Books Room
        ↓
Room Activated
        ↓
Resources Used
```

Angular Lazy Loading works similarly.

# Eager Loading vs Lazy Loading

| Eager Loading        | Lazy Loading          |
| -------------------- | --------------------- |
| Loads Everything     | Loads When Needed     |
| Large Initial Bundle | Small Initial Bundle  |
| Slow Startup         | Faster Startup        |
| Small Apps           | Enterprise Apps       |
| More Memory Usage    | Better Resource Usage |

# Lazy Loaded Route

## Lab 2

```typescript
{

path:'reports',

loadComponent:() =>

import(

'./reports/reports.component'

)

.then(

m => m.ReportsComponent

)

}
```

# Common Mistakes

## Mistake 1

```text
Lazy Loading Small Components
```

Not always beneficial.

---

## Mistake 2

```text
Making Everything Eager Loaded
```

Large bundle size.

---

## Mistake 3

```text
Lazy Loading Shared Utilities
```

Shared modules should usually remain shared.
