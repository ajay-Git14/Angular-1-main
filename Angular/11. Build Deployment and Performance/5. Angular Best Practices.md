# Best Practice 1: Feature-Based Folder Structure

## Bad Structure

```text
components

services

pipes

directives

everything mixed
```

---

Problem:

```text
Hard To Scale
```

---

## Good Structure

```text
features

├── complaints

├── residents

├── reports

├── settings
```

---

Benefit:

```text
Business-Oriented Structure
```

---

# Best Practice 2: Single Responsibility Principle

## Bad Component

```text
Login

Reports

Dashboard

API Calls

Validation

Everything Together
```

---

Problem:

```text
Huge Component
```

---

## Good Component

```text
Login Component

Dashboard Component

Report Component
```

---

Each does one job.

---

# Best Practice 3: Smart And Dumb Components

## Smart Component

Responsible For:

```text
API Calls

Business Logic

Data Loading
```

---

## Dumb Component

Responsible For:

```text
UI Rendering

Display Data

Raise Events
```

---

Architecture:

```text
Smart Component
       ↓
Data
       ↓
Dumb Component
```

---
