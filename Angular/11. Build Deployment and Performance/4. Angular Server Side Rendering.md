# Topic 4: Angular Server Side Rendering (SSR)

## Goal

Understand Angular Server Side Rendering (SSR), learn how Angular applications can render on the server before reaching the browser, and build enterprise applications with improved SEO, performance, and user experience.

---

## What

Angular SSR renders HTML on the server before sending it to the browser.

Traditional Angular:

```text
Browser
   ↓
Downloads JavaScript
   ↓
Builds UI
   ↓
User Sees Page
```

---

Angular SSR:

```text
Browser
   ↓
Requests Page
   ↓
Server Generates HTML
   ↓
Browser Receives Ready Page
   ↓
User Sees Content Immediately
```

---

## Real-Life Analogy

Imagine ordering food.

Without SSR:

```text
Receive Raw Ingredients
       ↓
Cook Yourself
       ↓
Eat
```

---

With SSR:

```text
Restaurant Cooks Food
         ↓
Ready Meal Delivered
         ↓
Eat Immediately
```

Similarly:

```text
Server Builds Page
        ↓
Browser Receives Ready HTML
```

---

## Why

Without SSR:

```text
Slower Initial Loading

Poor SEO

Search Engines See Limited Content

Blank Screen Initially
```

---

With SSR:

```text
Faster First Paint

Better SEO

Better User Experience

Improved Accessibility
```

# CSR vs SSR

## CSR (Client Side Rendering)

Traditional Angular:

```text
Browser
   ↓
Downloads JavaScript
   ↓
Builds UI
```

---

Characteristics:

```text
More Browser Work

Slower Initial Load

Good For Internal Apps
```

---

## SSR (Server Side Rendering)

```text
Browser
   ↓
Server Builds HTML
   ↓
Browser Displays Page
```

---

Characteristics:

```text
Fast Initial Load

SEO Friendly

Better User Experience
```

# CSR vs SSR Comparison

| CSR                    | SSR                      |
| ---------------------- | ------------------------ |
| Browser Renders        | Server Renders           |
| Slower First Load      | Faster First Load        |
| Poor SEO               | Better SEO               |
| Less Infrastructure    | More Infrastructure      |
| Good For Internal Apps | Good For Public Websites |
