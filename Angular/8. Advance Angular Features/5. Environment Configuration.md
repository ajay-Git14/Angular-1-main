# Topic 5: Environment Configuration

## Goal

Understand Environment Configuration in Angular, learn how to manage different environments such as Development, Testing, UAT, and Production, and build enterprise applications with environment-specific settings.

---

## What

Environment Configuration allows Angular applications to use different settings for different environments.

Example:

```text
Development
     ↓
Local API

Testing
     ↓
Test API

UAT
     ↓
UAT API

Production
     ↓
Production API
```

---

## Real-Life Analogy

Imagine a restaurant.

Training Kitchen:

```text
Practice Orders
```

---

Real Restaurant:

```text
Real Customers
```

---

Both environments are different.

Similarly:

```text
Development Environment

Production Environment
```

have different configurations.

---

## Why

Without Environment Configuration:

```text
Manual Code Changes

Risky Deployments

Wrong API Calls

Production Issues
```

---

With Environment Configuration:

```text
Automatic Configuration

Safer Deployments

Better Maintainability

Enterprise Ready
```

## Common Mistakes

### Mistake 1

```text
Hardcoding URLs
```

---

### Mistake 2

```text
Using Development API
In Production
```

---

### Mistake 3

```text
Storing Secrets
Inside Environment Files
```

---

## Important Note

Do NOT store:

```text
Passwords

API Secrets

Database Credentials

Private Keys
```

inside Angular environment files because Angular code is visible in the browser.

## Wrap-Up

### Key Takeaways

```text
Environment Configuration separates settings by environment.

API URLs should come from environment files.

Feature flags can be environment driven.

Development, UAT, and Production use different configurations.

Environment files improve deployment safety.
```
